# @pyrpc/types

TypeScript type definitions for [pyRPC](https://pyrpc.com). Generated by `pyrpc dev` / `pyrpc watch` / `pyrpc codegen` - reflects your actual Python backend procedures at compile time.

## How types are wired

`@pyrpc/types` ships as a stub. Your real types are generated into your source tree at `<client>/__pyrpc.d.ts` by the server-side `pyrpc dev` / `pyrpc watch` / `pyrpc codegen` commands.

`pyrpc dev` injects a tsconfig path alias so `import type { Types } from "@pyrpc/types"` resolves to that generated file:

```json
"compilerOptions": {
  "paths": {
    "@pyrpc/types": ["./__pyrpc.d.ts"]
  }
}
```

The alias is injected by `pyrpc_core/tsconfig.py` via jsonc-edit on every dev, watch, and codegen run. It preserves comments and trailing commas, is idempotent on repeat runs, and raises instead of silently overwriting an alias that already points elsewhere.

Before codegen runs, `Types` resolves to an empty interface. After codegen, it resolves to your actual procedure signatures - full autocompletion, no boilerplate. The generated file lives in your source tree and is committed to git, so it's diffable in PRs.

## Manual generation

```bash
pyrpc codegen http://localhost:8000
```
